# Gacha Forge Images 0.3.1 — 외부 확장 가져오기용

**이번 ZIP은 애드온 → 외부 확장 → 가져오기에서 사용하는 실제 확장입니다.**
Marinara Engine 2.5.0 / Gacha Forge 1.8.12 / 서버 PC의 localhost 접속을 대상으로 구현했습니다.

## 가져오기

1. **설정 → 애드온 → 외부 확장 → 가져오기**에서 `Gacha-Forge-Images-External-0.3.1.zip`을 선택합니다. ZIP을 풀 필요가 없습니다. 기존 `Gacha Forge Images`가 있다면 같은 항목을 **업데이트**합니다. 기존 확장을 삭제하거나 저장 공간을 초기화하지 마세요.
2. `Gacha Forge Images`의 코드를 검토하고 **Full page access(전체 페이지 접근)** 권한을 확인한 뒤 활성화합니다. 이는 엔진이 원래 제공하는 외부 확장 검토 절차입니다.
3. Gacha Forge에서 월드를 열고 **그림 아이콘 버튼**을 누릅니다. 버튼 자체를 끌면 이동하고, 클릭·탭하면 편집창이 열립니다. 버튼은 48×48 크기로 고정되며 드래그 표시나 크기 조절 손잡이가 없습니다.
4. 편집창은 **제목줄**을 끌어 이동하고 **오른쪽 아래 ↘**를 끌어 크기를 조절합니다. 위치와 크기는 게임 서버에 저장되어 다시 열어도 유지됩니다. 화면이 작아지면 창이 화면 밖으로 나가지 않도록 맞춥니다. 방향키로도 이동·크기 조절할 수 있으며 Shift를 누르면 10px씩 움직입니다.

기존 0.2.0·0.3.0 ZIP과 수정 전 소스는 별도 보관했습니다. 0.3.1은 같은 확장 ID의 기존 이미지 연결·설정 키를 이어서 사용합니다. 업데이트 후에는 엔진의 기존 검토·승인 절차를 다시 거칩니다.

## 0.3.1 수정 내용과 사용법

- 같은 스토리 안에서도 읽고 있는 **대사 위치**를 기준으로 현재 보이는 배경과 뒤쪽 CG를 구분합니다. 배경을 보고 있는데 뒤쪽 인물 CG가 자동으로 선택되던 문제를 수정했습니다.
- 스토리 선택 목록에 이야기 제목 또는 첫 문장과 장소를 표시합니다. 목록 아래에서 **이미지 썸네일·배경 장소·CG 제목·CG 표시 대사 범위**를 보고 구체적인 이미지를 선택합니다. 현재 화면과 연결된 이미지를 확인하지 못하면 임의로 다른 CG를 선택하지 않습니다.
- 아래의 **재생성**과 **프롬프트 확인**은 별도 버튼입니다. 재생성을 누르면 선택한 이미지를 생성하고 게임 서버에 저장합니다. 프롬프트 확인은 입력칸만 열고 접으며 이미지 생성은 하지 않습니다. 확인창에서 편집한 값은 같은 선택 상태에서 다음 재생성에도 사용합니다.
- 재생성 후에도 두 버튼이 그대로 남아 연속으로 다시 생성할 수 있습니다. 생성 중에는 버튼이 `재생성 중…`으로 바뀌고, 긴 저장 완료 문구는 표시하지 않습니다. 오류 안내는 유지합니다. 이미지 생성 서비스의 비용은 재생성 요청마다 발생할 수 있습니다.
- 배경을 선택하면 배경 긍정·부정 프롬프트만 보여주며 인물 입력칸을 만들지 않습니다. 지원되는 NAI에서는 배경 요청의 인물별 입력 배열과 좌표 사용을 비웁니다. 기존 연결은 수정하지 않습니다.
- **자동 배경 생성 OFF**와 수동 재생성 요청을 분리했습니다. 자동 생성 설정을 바꾸지 않고 사용자가 명시적으로 선택한 배경만 생성할 수 있습니다. 장면 장소 목록이 비어 있으면 저장된 대사의 장소와 해당 챕터의 실제 배경 정보를 확인합니다. CG가 없는 스토리에서도 동작합니다.
- 배경 재생성으로 인물 CG를 교체하지 않습니다. CG가 표시되는 대사 구간에는 기존 CG가 계속 보이고, 배경은 해당 스토리의 배경으로 저장됩니다.

서버 PC에서 `http://localhost:7860` 또는 실제 설정된 로컬 주소로 사용합니다. 가챠 포지의 Shadow DOM과 기존 서버 API에 연결하기 때문에 전체 페이지 접근 권한을 요청합니다. 일반 샌드박스 모드로는 이 기능에 접근할 수 없습니다. 외부 확장 가져오기 메뉴 자체가 숨겨져 있다면 엔진의 기존 외부 확장 허용 설정이 필요합니다. 이 확장이 해당 정책을 대신 켜거나 우회하지 않습니다.

## 기능

- 현재 보이는 이미지가 확인되면 기본 선택되며, 저장된 과거 스토리의 이미지를 직접 골라 CG·배경을 재생성할 수 있습니다.
- 생성 전 공통 긍정/부정 프롬프트와 인물별 외형·복장·동작·표정·부정 프롬프트·X/Y 좌표를 수정할 수 있습니다.
- CG의 기존 인물별 데이터에서 태그를 가져옵니다. 통 프롬프트를 임의로 사람별로 나누지 않습니다. 장면 복장·행동·표정·뒷모습을 반영하며, 월드의 `outfitCanon` 설정이 켜져 있으면 장착 복장을 참고합니다.
- 지원되는 NAI V4/V4.5/V5에서는 공통 프롬프트와 인물별 프롬프트를 네이티브 `char_captions`와 좌표로 전달합니다. V4/V4.5 인원 제한은 6명, V5는 22명이며 넘으면 일부 인물을 버리지 않고 중단합니다.
- 기존 자동 CG 생성과 캐릭터 배너 이미지 생성도 지원되는 NAI에서 인물별 입력을 사용합니다. 최초 자동 생성에는 확인 창을 띄우지 않습니다. 확인·수정 UI는 수동 재생성에 적용됩니다.
- 이미지 확장 전체 ON/OFF와 NAI 인물별 기능 ON/OFF를 제공합니다. 비NAI·지원되지 않는 NAI·프록시의 기존 자동 생성은 원래 경로로 보냅니다. 수동 재생성도 그 연결의 기존 이미지 생성 입구를 사용합니다.
- 새 이미지가 생성되고 갤러리 업로드와 게임 서버 저장이 성공한 뒤, 저장 내용을 다시 읽어 확인하고 표시를 바꿉니다. 실패·재시도·중복 요청 때 기존 이미지와 스토리 진행을 유지합니다.
- 배경은 해당 장면에만 적용합니다. 동일 장소를 쓰는 다른 장면은 바꾸지 않습니다.
- 확장을 다시 불러와도 이미지 선택이 유지됩니다. 비활성화하면 원본 이미지 표시로 돌아가며 생성한 갤러리 이미지를 지우지 않습니다.
- 편집창을 열어도 게임 화면을 계속 조작할 수 있습니다. 생성 중에도 편집창을 닫을 수 있고 요청과 저장은 계속됩니다. 닫기는 생성 취소가 아닙니다. 재생성·프롬프트 확인 버튼은 창 아래에 유지됩니다.

## 기존 데이터를 보존하는 방식

엔진 파일과 Gacha Forge 파일은 수정하지 않습니다. 공식 읽기 전용 데이터 조회 API로 Gacha Forge 문서를 읽고, 새 이미지의 참조와 이력은 **마리나라 서버의 외부 확장 저장 공간**에 저장합니다. 이 저장 공간은 서버 `app_settings`의 `extension-storage:<확장 ID>`이며, 브라우저 임시 메모리나 브라우저 로컬 저장소가 아닙니다. 이미지 파일은 원래 마리나라 갤러리 업로드 API에 저장됩니다. 장면 ID에 연결하므로 게임을 다시 열거나 서버를 다시 시작해도 확장이 활성화되어 있으면 같은 장면에 적용됩니다.

원본 스토리·CG 문서·세이브·재화·보상·캐릭터 카드·월드 설정은 덮어쓰지 않습니다. 원본 장면의 내용이 그대로인데 내부 수정 번호만 변한 경우에도 새 이미지 연결이 유지되도록 원본 내용의 지문을 함께 저장합니다. 원본 장면의 내용 자체가 다시 작성된 경우에는 잘못된 장면에 이미지를 덮어씌우지 않도록 원본 표시를 우선합니다. 0.2.0 기록은 기존 수정 번호 규칙으로 읽으며 다음 생성부터 내용 지문을 추가합니다.

**확장을 끄면 원본 이미지가 표시됩니다. 확장 없이 원본 Gacha Forge가 새 이미지를 직접 읽는 방식은 아닙니다.** 파일과 장면 연결은 삭제하지 않으며 다시 켜면 적용됩니다.

NAI 키를 브라우저에서 읽지 않습니다. 생성할 때 서버의 기존 연결 복제 API가 암호화된 인증을 유지한 임시 연결을 만들고, 그 사본에만 이번 요청의 네이티브 NAI 입력을 설정합니다. 원래 이미지 생성 API로 전송한 뒤 임시 사본을 정리합니다. 사용자의 원래 연결과 기본 프롬프트·모델·저장 설정은 그대로 둡니다. 생성 중 임시 연결이 연결 목록에 잠깐 나타날 수 있습니다. 중단된 세션의 임시 연결은 확장이 기록한 것만 확인하며, 다른 생성 요청이 사용 중이지 않고 30분이 지난 사본을 다음 실행 때 정리합니다.

브라우저가 임시 사본 생성 직후 기록을 저장하기 전에 종료되거나 정리 요청 자체가 실패하면 임시 사본이 남을 수 있습니다. 원래 연결은 삭제하지 않으며, 확장도 출처를 확인하지 못한 연결을 자동 삭제하지 않습니다.

확장 전용 저장 공간은 엔진 기준 1MB이며 이미지 자체는 넣지 않고 연결·이력·프롬프트만 저장합니다. 공간 부족으로 저장이 거절되면 기존 이미지 참조를 유지하며 새로 생성된 파일은 갤러리에 남을 수 있습니다. 확장 저장 데이터를 삭제하면 장면별 연결 정보는 사라집니다.

게임을 다른 곳으로 옮길 때는 엔진의 **전체 백업**으로 `storage`와 `gallery`를 함께 보존해야 합니다. 별도 시험 서버에서 실제 전체 백업 ZIP을 만들고 두 폴더를 새 데이터 폴더에 복원한 뒤 CG·배경 연결과 파일을 확인했습니다. 사용자 실제 세이브와 프로필 가져오기 화면을 통한 복원은 실행하지 않았습니다. 확장 ZIP만 가져오면 게임 데이터와 생성한 이미지가 함께 옮겨지는 것은 아닙니다.

## 검증

실행한 검사:

- 수정하지 않은 엔진 2.5.0을 별도 데이터 폴더에서 실행하고 실제 API로 연결 복제 → 요청 설정 → 이미지 생성 → 사본 정리까지 검사했습니다. NAI 1인/2인에서 공통·인물별 긍정/부정 프롬프트와 좌표가 최종 네이티브 JSON에 들어갔습니다. 유료 서비스 응답은 시험 이미지로 대체했습니다.
- 같은 격리 엔진의 실제 외부 확장 생성 API가 이 코드를 `client / full_page_access / 비활성 초안`으로 받아들이는 것을 확인했습니다.
- 엔진이 실제 사용하는 가져오기 파서로 ZIP을 읽어 확장 1개와 JavaScript·권한이 정상 인식되는지 확인했습니다.
- Edge Chromium PC 1280×800, 모바일 가로 844×390에서 원본 Gacha Forge 스토리 화면과 이 단일 스크립트를 함께 실행했습니다. 다인 CG 재생성·프롬프트 수정·자동 1인 CG·다인 배너·생성 실패/재시도·읽던 문장 위치·이미지 유지·확장 재로딩·OFF·비NAI·미지원 NAI·비활성화 시 정리를 검사했습니다. 원본 데이터와 원래 이미지 연결이 변하지 않았고 임시 연결이 남지 않았습니다. 이 브라우저 검사에서는 통신 응답과 월드 로딩에 시험 데이터를 사용했습니다.
- 실제 사용 중인 설치본에서는 가챠 포지 문서에 대한 읽기 전용 조회가 가능한 것을 확인했습니다. 원본 파일과 세이브를 수정하지 않았고 확장을 대신 설치·승인하지 않았습니다.
- ZIP 압축 해제 후 구성과 파일 해시를 검사했습니다.
- 실제 외부 확장 빌드에서 아이콘 하나·고정 48px·버튼 전체 이동·클릭/드래그 구분·편집창 이동/크기 조절·다시 열기/확장 재로딩 후 배치를 검사했습니다. 게임 저장 실패를 추가로 주입해 기존 이미지와 읽던 위치가 유지되는지 확인했습니다.
- 가로 모바일 크기의 터치 드래그·탭, 실제 과거 장면 선택 후 재생성, 생성 중 편집창을 닫은 뒤 저장 완료, 0.2.0 이미지 연결 이력의 유지도 검사했습니다. 터치는 브라우저 에뮬레이션이며 실기기 검사는 아닙니다.
- 수정하지 않은 엔진 2.5.0의 실제 확장 저장·갤러리 업로드 API로 CG와 장면별 배경을 저장했습니다. 별도 서버 프로세스 재시작과 전체 백업 ZIP의 `storage`/`gallery`를 새 폴더에 복원한 서버에서 장면 연결 및 파일 해시가 유지됐습니다. 원본 스토리·진행·재화는 동일했습니다. 이미지 제공자 응답은 시험 PNG로 대체해 과금 호출은 없었습니다.
- 실제 엔진 API로 같은 확장 ID를 0.2.0 시험 코드에서 새 버전으로 업데이트하고 재승인한 뒤 기존 저장 데이터와 배치가 유지되는지 확인했습니다.
- 앞 대사는 배경, 뒤 대사 5~10은 인물 CG인 동일 스토리를 원본 화면에서 재현했습니다. 앞부분에서 도구를 열었을 때 배경이 선택되고 인물 입력칸이 0개이며, 배경을 두 번 연속 생성해도 뒤쪽 CG 저장 데이터와 이미지가 그대로인 것을 확인했습니다. 독립된 두 버튼과 완료 문구 제거도 검사했습니다.
- 자동 배경 OFF에서 명시적인 수동 배경 생성과 재진입, 장소 목록·CG 문서가 없는 스토리의 챕터 배경 선택·표시·저장을 검사했습니다. 수정하지 않은 엔진의 최종 NAI 요청에서 배경은 인물 입력 0개·좌표 OFF, 기존 1인·2인 CG는 각각 1개·2개인지 확인했습니다.
